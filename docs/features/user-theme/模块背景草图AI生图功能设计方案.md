# 模块背景草图 AI 生图功能设计方案

## 1. 产品决定

当前版本只允许商家设计单个模块背景内部的画面，不开放整个页面的模块布局编辑。

页面、模块顺序、业务结构和交互继续由小程序代码控制。商家能够表达的是：当前背景里主体放在哪里、哪里需要留白、希望出现哪些装饰、使用什么颜色和氛围，以及局部区域需要怎样修改。

## 2. 目标与成功标准

目标是让不会写 Prompt、不会专业绘图的商家，也能用搭建草图、回答少量问题和添加区域备注的方式，把视觉意图准确传给 AI。

首版成功标准：

- 商家能在 3 分钟内完成一个模块画面草图并发起生成。
- 商家在最多两次生成内应用候选图的比例达到产品设定目标。
- 生成结果的主体位置、文字安全区和装饰关系符合已确认的视觉意图。
- 业务文字保持可编辑且清晰，不被生成到背景中。
- 商家可以指出候选图的局部问题并继续修改，不必从头描述。

## 3. 功能位置

功能继续附着在当前模块的“图片与背景”属性中，不增加独立一级导航。

```text
页面导航
  -> 选择页面
  -> 选择模块
  -> 图片与背景
  -> AI 设计背景
  -> AI 视觉工作室
```

现有“AI 改图”调整为两个明确入口：

- 搭画面生成：创建新的背景构图。
- 保留构图换风格：沿用当前图片构图，只改变视觉语言。

上传图片和素材库继续与 AI 入口并列，商家不必经过 AI 才能完成装修。

## 4. AI 视觉工作室布局

AI 视觉工作室使用 PC 全屏工作区，保留当前装修草稿和预览上下文，不跳出商家工作台。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 返回  首页 · 顶部轮播图  750 x 360       撤销  重做  帮助  关闭     │
├──────────────┬───────────────────────────────────┬───────────────────┤
│ 构图模板     │                                   │ AI 设计助手       │
│ 商品/主体    │        当前模块比例画布            │                   │
│ 文字安全区   │                                   │ 已知信息          │
│ 场景元素     │    [标题安全区]       [商品]       │ 待确认问题        │
│ 备注         │                          ↖         │ 区域备注          │
│ 画笔/箭头    │                     这里光线更亮    │ AI 理解结果       │
│              │                                   │                   │
├──────────────┴───────────────────────────────────┴───────────────────┤
│ 重置草图          保存意图草稿                   检查并生成 2 个方案 │
└──────────────────────────────────────────────────────────────────────┘
```

布局要求：

- 顶部工具栏高度稳定，显示模块名称、输出尺寸和撤销/重做。
- 左侧是语义工具，不使用大量文字说明；图标按钮带工具提示。
- 中间画布始终保持当前模块的真实宽高比。
- 右侧合并问题、备注和 AI 理解结果，避免多个弹窗来回切换。
- 底部只保留重置、保存意图草稿和生成三个明确操作。

## 5. 首次进入

商家点击“AI 设计背景”后，系统先自动带入：

- 当前页面和模块。
- 插槽输出宽高、比例和渲染方式。
- 当前背景或模板背景。
- 当前模块的业务文字角色和文字安全区。
- 商家的品牌色、Logo 和可用平台字体。
- 当前模块允许的 AI 模式、主体类型和禁止元素。

商家只需选择一个起点：

1. 从构图模板开始，推荐给大多数商家。
2. 从当前背景开始，适合保留现有构图。
3. 从空白模块画布开始，只提供给明确知道构图的商家。

空白画布仍使用语义积木，不把纯手绘图作为唯一输入。

## 6. 画布工具

### 6.1 构图模板

模板由模块能力决定，不同模块不能展示同一套无效构图。

首页 Banner 首版提供：

- 左文右图。
- 右文左图。
- 居中主体。
- 上文下图。
- 场景氛围。

选择模板会同时创建主体区域和文字安全区，商家可以在允许范围内微调。

### 6.2 语义元素

首版语义元素包括：

- 商品：从当前商家的商品库选择。
- 通用主体：咖啡杯、咖啡豆、甜点、门店或系统支持的其他主体。
- 文字安全区：只表示需要干净背景，不会把文字生成到图片里。
- 场景：咖啡馆、木桌、窗边、纯色摄影棚等。
- 装饰：植物、咖啡豆、纸张纹理等受控元素。
- 避让区：禁止主体、装饰和高复杂度纹理出现的区域。

每个元素拥有稳定边界，只允许移动和受限缩放。是否允许旋转、复制或删除由元素类型决定。

### 6.3 辅助标注

画笔、箭头和圈选用于补充无法由语义元素直接表达的信息，例如光线方向或装饰密度。

辅助标注必须满足：

- 可以单独选择和删除。
- 可以绑定一条区域备注。
- 不会被当作最终视觉素材直接保留。
- 在提交 AI 前转换为结构化描述和一张视觉引导图。

## 7. 区域备注

商家添加备注时，必须先选择模块画布、一个元素或一个圈选区域。

备注由“动作 + 对象 + 补充说明”组成：

```text
动作：增加 / 减少 / 移动 / 保持 / 避开 / 更换
对象：当前选中的主体、装饰、颜色、光线或纹理
说明：商家输入的简短自然语言
```

示例：

- 减少 · 右侧植物 · 不要挡住商品轮廓。
- 增加 · 左上区域光线 · 像早晨从窗户照进来。
- 保持 · 商品主体 · 杯型、Logo 和配料必须与原图一致。
- 避开 · 标题安全区 · 不要出现咖啡豆和复杂纹理。

没有锚点的普通便签不允许提交，避免模型无法判断备注指向。

## 8. 动态问题

问题面板只询问草图和商家资料中尚未表达的信息，每次最多显示 3 至 5 个问题。

问题优先级：

1. 用途和最重要主体。
2. 必须保持的商品或品牌特征。
3. 颜色和明暗倾向。
4. 摄影、插画或材质风格。
5. 氛围、光线和装饰密度。

系统已经知道的信息不重复询问。例如已从 Logo 提取品牌色时，直接提供“使用品牌色”选项；已经选择具体商品时，不再询问商品名称。

问题使用色卡、图片选项、分段选择和单选菜单，不要求商家再次编写长 Prompt。

## 9. AI 理解结果

生成前，右侧展示一份可检查的结构化摘要：

```text
用途：首页顶部轮播图
主体：生椰拿铁，位于右侧，占画面约 38%
文字安全区：左侧约 42%，保持低纹理和足够对比
场景：自然采光咖啡馆，木质桌面
装饰：右上少量绿色植物
色调：奶油暖色，继承品牌棕色
必须保持：商品杯型、Logo、配料和拍摄角度
禁止出现：随机文字、价格、按钮、二维码
```

商家可以点击摘要项回到对应元素或答案修改。点击“生成图片”即代表确认，不再增加确认弹窗。

以下情况必须阻止生成：

- 没有主体或场景方向。
- 文字安全区与主体严重重叠。
- 两条区域备注互相冲突。
- 商品要求严格还原但缺少商品参考图。
- 当前模块不支持所选元素或生成类型。

## 10. 结构化视觉意图

画布不能只导出一张草图图片。系统需要同时保存版本化 JSON 和视觉引导图。

```json
{
  "schemaVersion": 1,
  "slotKey": "homeBanner",
  "slotSpecVersion": 1,
  "canvas": {
    "width": 750,
    "height": 360,
    "renderMode": "COVER"
  },
  "visualPreset": "WARM_HANDMADE",
  "compositionPreset": "LEFT_COPY_RIGHT_SUBJECT",
  "subjects": [
    {
      "id": "subject_1",
      "type": "PRODUCT",
      "productId": 82731,
      "box": { "x": 0.57, "y": 0.16, "width": 0.34, "height": 0.70 },
      "identityPolicy": "STRICT"
    }
  ],
  "textSafeAreas": [
    { "x": 0.06, "y": 0.18, "width": 0.42, "height": 0.58 }
  ],
  "scene": {
    "type": "CAFE",
    "lighting": "SOFT_NATURAL",
    "colorTone": "CREAM_WARM"
  },
  "elements": [
    { "id": "plant_1", "type": "PLANT", "density": "LOW", "position": "RIGHT_TOP" }
  ],
  "annotations": [
    {
      "targetId": "plant_1",
      "action": "REDUCE",
      "text": "不要挡住商品轮廓"
    }
  ],
  "questionAnswers": {
    "renderingStyle": "COMMERCIAL_PHOTO",
    "mood": "FRESH"
  }
}
```

这里的归一化坐标只存在于 AI 视觉意图中，用于描述背景内部构图；它们不能写入发布的 ThemeConfig，也不能改变小程序页面布局。

## 11. 生成链路

```text
模块画面草图
  -> 校验结构化视觉意图
  -> 导出视觉引导图
  -> 将意图转换为模型指令和约束
  -> 调用图片模型
  -> 按插槽尺寸处理图片
  -> 检查主体、安全区、随机文字和禁止元素
  -> 展示两个 AI 候选图
```

视觉引导图应由经过验证的 Canvas 库导出，不手写复杂的选择、缩放、图层和撤销逻辑。

当前 Provider 只支持一张参考图。普通背景可以把视觉引导图作为该参考图；若同时要求严格还原具体商品，应优先使用商品抠图与 AI 背景确定性合成，或升级为支持多参考图和蒙版的模型链路，不能仅依靠 Prompt 承诺商品一致性。

## 12. 候选图与修改闭环

候选图继续支持预览、接受和应用，但用户层文案调整为：

- 放到页面看看：仅在 H5 预览中临时显示。
- 保存到素材库：不修改装修草稿。
- 应用到当前模块：写入当前装修草稿。

选择候选图后提供常用修改动作：

- 主体更大或更小。
- 主体向左或向右。
- 装饰减少。
- 画面更亮或更暗。
- 文字区更干净。
- 更换颜色或风格。
- 圈选区域并添加备注。

每次修改保存为视觉意图的新版本，并记录相对上一版本的变化。不能覆盖原始意图或要求商家从头搭建。

## 13. 保存与退出

- 视觉意图草稿与装修草稿分开保存。
- 商家退出视觉工作室后可以继续上次的草图。
- 切换模块时提示保存或放弃尚未保存的意图草稿。
- AI 候选图未经应用不会修改当前模块背景。
- 应用候选图后仍需通过现有装修方案的保存、预览和发布流程。

## 14. 与当前代码的衔接

### 工作台

`workbench.html` 中现有模块导航、“图片与背景”、AI 任务轮询、候选图预览和应用流程可以复用。需要新增全屏 AI 视觉工作室、画布状态和视觉意图草稿。

### AI 请求和任务

`DecoratorAiTaskRequest` 目前以自然语言字段为主，需要增加版本化视觉意图引用或受控 JSON。`ai_generation_tasks` 需要保存意图版本、视觉引导图和父任务关系，避免只保留最终 prompt。

### 提示词和 Provider

`DecoratorPromptBuilder` 应从结构化视觉意图生成指令。Provider 接口需要明确是否支持视觉引导图、蒙版和商品参考图，不能由前端假设模型能力。

### 质量校验

当前候选图只校验图片尺寸和透明通道，OCR/视觉状态仍为 `NOT_CHECKED`。新功能上线前需要补充主体位置、文字安全区、随机文字、Logo、二维码和禁止元素检查。

### 小程序运行时

小程序继续只读取最终背景素材和独立文字层，不读取草图、备注、视觉意图坐标或 Canvas 数据。

## 15. 开发阶段

### Phase 1：结构化意图与模板

1. 定义模块视觉意图 Schema 和版本策略。
2. 为首页 Banner 建立五个构图模板。
3. 实现主体、文字安全区、场景和装饰语义元素。
4. 实现视觉意图草稿的保存和恢复。

### Phase 2：画布与备注

1. 接入成熟 Canvas 库。
2. 实现选择、移动、缩放、删除、撤销和重做。
3. 实现画笔、箭头、圈选和锚定区域备注。
4. 导出结构化 JSON 和视觉引导图。

### Phase 3：问题与理解结果

1. 根据组件 Profile 和已有信息生成缺失问题。
2. 实现色卡、图片选项和分段选择。
3. 构建 AI 理解摘要和冲突校验。
4. 保存问题答案和意图版本。

### Phase 4：生成与校验

1. 从视觉意图生成模型输入。
2. 接入视觉引导图和商品身份处理。
3. 增加主体、安全区和禁止元素校验。
4. 接入现有候选图、预览、接受和应用流程。

### Phase 5：修改闭环

1. 增加候选图快捷修改动作。
2. 支持圈选候选区域继续备注。
3. 保存父子意图和修改差异。
4. 记录首次应用率、生成次数和放弃原因。

## 16. 首版范围

首版只实现首页顶部 Banner，跑通完整闭环后再扩展到欢迎横幅、关于我们图片和其他背景模块。

首版不做：

- 页面模块排序、缩放、隐藏或新增。
- 整页布局草图。
- AI 生成完整页面截图。
- 纯自由手绘作为唯一输入。
- 业务文字进入 AI 背景。
- 任意 CSS、WXML、Vue 或页面代码生成。
- 像素级构图还原承诺。

## 17. 验收场景

1. 商家选择“左文右图”，添加一个商品，左侧安全区自动建立，生成结果不得在左侧出现复杂主体。
2. 商家在右上植物上画圈并备注“植物少一点”，AI 理解结果必须显示该约束。
3. 商家选择具体商品并要求严格还原，但商品缺少参考图时，系统必须阻止生成。
4. 商家生成候选后选择“主体再大一点”，新任务必须继承原意图并只记录尺寸变化。
5. 商家退出后重新打开当前模块，能够恢复未生成的视觉意图草稿。
6. 商家预览候选时不修改装修草稿，只有“应用到当前模块”才写入草稿。
7. 背景生成后，标题和副标题仍由文字层渲染并通过文字适配检查。
