# 商家装修功能代码地图

这份表解决一个实际问题：老师问到某个功能时，应该打开哪个文件、找哪个方法。

> 行号是当前仓库行号。以后代码增加后行号可能变化，优先用“方法名”搜索。

## 1. 总流程入口

```text
后台工作台
  -> 前端 state.config
  -> H5 postMessage 预览
  -> PUT 草稿
  -> POST 发布
  -> theme_versions
  -> store_theme_bindings
  -> GET /api/mini/skin
  -> themeRuntime.apply
  -> pages/index/index.vue 等页面
```

| 功能 | 入口文件 | 关键位置 |
| --- | --- | --- |
| 后台工作台页面 | `src/main/resources/templates/coffee/decorator/workbench.html` | 控件、状态、请求、预览、保存、发布都在这个文件 |
| 后台接口入口 | `src/main/java/com/ruoyi/project/coffee/decorator/api/DecoratorThemeController.java` | 所有主题管理 API |
| 后端业务逻辑 | `src/main/java/com/ruoyi/project/coffee/decorator/theme/DecoratorThemeService.java` | 权限、校验、草稿、发布、门店绑定 |
| 小程序顾客端主题接口 | `src/main/java/com/ruoyi/project/coffee/decorator/api/CustomerThemeController.java` | `/api/mini/skin`、已发布主题、预览主题 |
| 小程序主题 API 调用 | `RuoYi-AbuCoder-UniAppWx/Ruoyi-AbuCoder-UniApp-WX/api/theme.js` | 小程序请求后端的入口 |
| 小程序主题运行时 | `RuoYi-AbuCoder-UniAppWx/Ruoyi-AbuCoder-UniApp-WX/theme/runtime.js` | 配置读取、规范化、状态和样式转换 |

### 保存草稿时重点看什么

打开 `saveDraft()`，重点看这几步：

```text
requireTheme(... THEME_EDIT)
  -> configValidator.validate(configJson)
  -> validateAssetReferences(...)
  -> updateDraft(... revision ...)
  -> replaceDraftReferences(...)
```

这就回答了老师的“保存时到底做了什么”。

### 发布时重点看什么

打开 `publish()`，重点看：

```text
selectDraftForUpdate()
  -> 校验草稿
  -> 计算 configHash
  -> insertVersion()
  -> replaceVersionReferences()
  -> bindFollowingStores() 或 bindIndependentStore()
```

## 16. 汇报时不要只报文件名

不要说：

> “保存功能在 Java 文件里。”

要说：

> “保存从 `workbench.html` 的 `saveDraft()` 进入，调用 `PUT /themes/{themeId}/draft`；请求进入 `DecoratorThemeController.saveDraft()`，再进入 `DecoratorThemeService.saveDraft()`，经过配置、素材和字体校验后，通过 Mapper 的 `updateDraft` 按 revision 更新 `theme_drafts.config_json`。”

这才算真正找到了实现，而不是只知道文件名。
