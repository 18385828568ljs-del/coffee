# AI 生图与文字适配系统设计方案

## 1. 目标

本方案解决商家无法准确描述 AI 图片，以及生成背景后文字不清晰、位置不协调、字体与背景不匹配的问题。

首版只覆盖首页顶部 Banner。成功标准是商家能在最多两次生成内应用一个可发布的轮播项，同时保证文字可读、位置合理、背景与文字风格协调。

## 2. 产品原则

1. AI 只生成无业务文字背景，标题和副标题始终由小程序文字层渲染。
2. 商家通过模板、语义积木和有限调整表达意图，画笔、箭头和圈选只作为辅助标注。
3. 背景构图和文字样式属于同一个视觉方案，但可以分别修改。
4. 文字位置由构图模板与安全区决定，不能使用任意坐标。
5. 可读性属于发布门槛，审美协调属于系统建议。
6. 每个轮播项独立保存背景、文案、构图和文字样式。
7. 首版只设计模块背景内部的画面，不改变页面模块顺序、尺寸或业务结构。

## 3. 商家操作流程

```text
选择“搭画面生成”
  -> 选择视觉方案
  -> 选择构图模板
  -> 添加一个商品或主体
  -> 添加可选的区域备注和辅助标注
  -> 填写标题和副标题
  -> 系统展示文字安全区
  -> 确认 AI 理解结果
  -> 生成两个无文字背景候选
  -> 校验候选的安全区与主体位置
  -> 选择一个候选
  -> 系统推荐文字样式方案
  -> 自动完成文字适配检查
  -> 商家预览、微调并应用到轮播项
```

现有“图片风格改写”继续保留，与“搭画面生成”并列。前者保留参考图构图，后者创建新构图。

## 4. 编辑器信息架构

### 4.1 背景页签

- 生成方式：搭画面生成、图片风格改写、上传图片、素材库。
- 视觉方案：醒目促销、清爽现代、温暖手作、精致品牌。
- 构图模板：左文右图、右文左图、居中主体、场景氛围。
- 主体：首版最多一个商品或一个系统语义主体。
- 装饰：首版最多两个系统提供的装饰元素。
- 备注：锚定到模块、语义元素或圈选区域，并包含结构化动作和简短说明。
- 辅助标注：允许画笔、箭头和圈选，但不能作为唯一输入。
- 候选数量：默认两个。

### 4.2 文字页签

- 标题：建议中文不超过 14 字，最多两行。
- 副标题：建议中文不超过 24 字，最多两行。
- 文字样式方案：展示四个使用当前文案和当前背景的真实预览。
- 颜色策略：自动适配、亮色文字、深色文字、品牌色。
- 位置：跟随构图模板，只显示允许的位置预设。
- 高级设置：平台字体、字号、字重、行高、字距、颜色和衬底。
- 操作：恢复推荐样式。

“AI 艺术字”保留为装饰文字入口，不作为标题、副标题、价格、按钮或其他业务文字。

## 5. 视觉方案

视觉方案不是一张固定模板，而是背景生成规则与文字样式方案的组合。

| 视觉方案 | 背景倾向 | 文字倾向 | 适用场景 |
|---|---|---|---|
| 醒目促销 | 高识别主体、较强色彩对比 | 粗字重、紧凑层级、明确衬底 | 新品、限时活动 |
| 清爽现代 | 干净留白、低装饰密度 | 现代平台字体、中等字重、宽松行高 | 日常品牌 Banner |
| 温暖手作 | 自然材质、柔和光线 | 温和字重、适度字距、暖色体系 | 咖啡故事、手作产品 |
| 精致品牌 | 克制色彩、精细材质 | 高对比层级、简洁字体、少量装饰 | 品牌形象、会员主题 |

商家选择视觉方案后，系统同时得到背景 `stylePreset` 和默认文字 `textStylePreset`。更换文字样式不触发重新生图。

## 6. 构图与文字安全区

首版构图只使用标准化区域，不使用任意坐标：

| 构图 | 主体区域 | 文字区域 | 默认对齐 |
|---|---|---|---|
| 左文右图 | 右侧约 45% | 左侧约 45% | 左对齐、垂直居中 |
| 右文左图 | 左侧约 45% | 右侧约 45% | 右对齐、垂直居中 |
| 居中主体 | 中部偏下 | 上部或下部安全区 | 居中 |
| 场景氛围 | 中部和边缘场景元素 | 复杂度最低的预设区域 | 由模板确定 |

背景生成必须把安全区作为硬约束。候选生成完成后再次检测安全区；若商品、人物、Logo、随机文字或高复杂度纹理侵入安全区，则候选不可进入可应用状态。

文字位置冲突时按以下顺序处理：

1. 在当前构图允许的位置中切换。
2. 切换文字样式或增加衬底。
3. 重新生成背景。

系统不得通过缩小到不可读字号、超出画布或覆盖主体来解决冲突。

## 7. 文字适配规则

### 7.1 清晰度

- 按文字实际覆盖区域而不是整张图片计算对比度。
- 普通文字对比度至少为 `4.5:1`。
- 大标题对比度至少为 `3:1`。
- 优先在深色和浅色文字策略之间切换。
- 仍不合格时使用视觉方案定义的半透明纯色衬底。
- 阴影只能作为辅助，不能作为对比度不合格的唯一补救方式。

### 7.2 排版

- 标题和副标题均最多两行。
- 使用真实文案、真实平台字体和真实 Banner 尺寸测量文本边界。
- 检查文字是否溢出、裁切、贴近边缘或与轮播指示点冲突。
- 字号、行高和字距必须落在文字角色注册表允许的范围内。

### 7.3 协调性

- 背景和文字默认继承同一个视觉方案。
- 标题与副标题必须保持稳定的字号和字重层级。
- 商家修改平台字体、字号、字重或颜色后重新执行适配检查。
- 协调性不足只提示并提供替换方案，不作为绝对发布阻断条件。

## 8. 自动检查与发布规则

| 检查项 | 处理方式 |
|---|---|
| 文字溢出或裁切 | 阻止应用和发布 |
| 对比度不合格 | 自动修正；失败后阻止应用和发布 |
| 文字覆盖商品、人物或主要主体 | 切换允许位置；失败后要求重新生成 |
| 背景随机文字、Logo、价格或二维码 | 候选拒绝 |
| 安全区纹理过于复杂 | 候选拒绝或重新生成 |
| 字体与背景协调度较低 | 警告并推荐其他文字样式方案 |
| H5 与微信真机测量结果不一致 | 阻止该配置发布 |

工作台不展示抽象的“设计分数”，只展示可执行结果，例如“标题与商品重叠，已切换到左侧”或“当前背景无法保证文字清晰，请重新生成”。

## 9. 数据结构建议

当前 `assets.homeBanner` 是图片数组，而 `content.homeBanner`、`layout.homeBanner` 和 Banner 文字样式是共享配置。需要迁移为独立轮播项：

```json
{
  "homeBannerItems": [
    {
      "id": "banner_item_01",
      "assetId": 1201,
      "title": "夏日椰香新品",
      "subtitle": "清爽上线，限时尝鲜",
      "visualPreset": "WARM_HANDMADE",
      "compositionPreset": "LEFT_COPY_RIGHT_SUBJECT",
      "safeAreaPreset": "LEFT_CENTER_LARGE",
      "textStylePreset": "WARM_HANDMADE_PRIMARY",
      "textOverrides": {
        "title": { "fontId": 3, "fontSize": 26, "fontWeight": 800 },
        "subtitle": { "fontId": 3, "fontSize": 12, "fontWeight": 500 }
      },
      "readability": {
        "status": "PASSED",
        "checkedAssetChecksum": "...",
        "checkedAt": "2026-08-30T00:00:00Z"
      }
    }
  ]
}
```

兼容迁移规则：旧 `assets.homeBanner` 中的每张图片转换为一个轮播项；旧的共享标题、构图和文字样式复制到每个轮播项，商家保存后再进入新结构。

一次 AI 任务还应保存版本化的视觉意图：

```json
{
  "schemaVersion": 1,
  "usage": "HOME_BANNER",
  "visualPreset": "WARM_HANDMADE",
  "compositionPreset": "LEFT_COPY_RIGHT_SUBJECT",
  "subject": { "type": "PRODUCT", "productId": 82731, "scale": "MEDIUM" },
  "decorations": ["BOTANICAL"],
  "safeAreaPreset": "LEFT_CENTER_LARGE",
  "textMetrics": { "titleLength": 8, "subtitleLength": 10 }
}
```

结构化意图必须作为任务快照保存，不能只拼成 prompt 后丢弃。

## 10. 与当前代码的差距

### 工作台

`workbench.html` 已有逐项文字参数和 Banner 左、中、右位置选择，但缺少视觉方案、样式方案预览、自动适配结果和每个轮播项的独立配置。

### 小程序运行时

`typography-registry.js` 已支持颜色、字号、字重、行高、字距、平台字体和阴影，可继续作为底层文字令牌。需要增加轮播项级令牌覆盖和衬底配置。

`layout-registry.js` 当前只把 `contentPreset` 转成样式，虽然配置中保存了 `safeAreaPreset`，但安全区没有参与实际布局或校验，需要补齐。

`pages/index/index.vue` 当前在整个 swiper 上方渲染一个共享 `hero-copy`。需要把文字层移入每个 `swiper-item`，并使用对应轮播项的文案、构图和文字样式。

### AI 任务

当前 Provider 只接收 prompt、一张参考图和目标尺寸。首版只能承诺预设区域级控制；若要同时严格还原商品并精确控制构图，需要升级为支持蒙版或多参考图的模型链路。

### 候选质量

当前 AI 候选的 OCR/视觉校验状态仍为 `NOT_CHECKED`，素材接受时直接进入 `APPROVED`。上线新流程前必须补充内容安全、随机文字、主体侵入和安全区复杂度检查。

## 11. 开发顺序

### Phase 1：轮播项与文字层

1. 引入 `homeBannerItems` 数据结构和旧配置迁移。
2. 将小程序 Banner 文字层移动到每个轮播项内部。
3. 让轮播项独立保存文案、构图和文字覆盖参数。
4. 增加 H5 与微信真机的文字边界一致性测试。

### Phase 2：文字样式方案

1. 建立四套文字样式方案注册表。
2. 工作台使用真实背景和真实文案展示方案预览。
3. 增加自动深浅色策略、衬底和恢复推荐样式。
4. 保留受限的高级参数编辑。

### Phase 3：文字适配检查

1. 实现文本尺寸、溢出和裁切检测。
2. 实现文字区域对比度检测。
3. 实现安全区复杂度和主体重叠检测。
4. 将硬性失败接入应用与发布校验。

### Phase 4：搭画面生成

1. 保存版本化视觉意图。
2. 增加构图模板和商品主体选择。
3. 根据安全区生成无文字背景候选。
4. 对候选执行视觉和内容安全检查。
5. 记录生成、修改、应用和放弃行为。

## 12. 验收指标

- 商家在最多两次生成内应用候选图的比例。
- 首次生成后直接应用的比例。
- 每个已应用轮播项的平均生成次数。
- 因文字不清晰、位置冲突或风格不协调而放弃的比例。
- 发布前文字溢出、裁切和对比度不合格的漏检数量为零。
- H5 预览与微信真机中关键文字边界和换行结果一致。

## 13. 首版不做

- AI 将业务文字直接生成到背景图片。
- 商家重新排列、缩放或新增页面业务模块。
- 商家任意拖动、旋转或输入坐标。
- 商家上传任意字体文件。
- 仅凭纯自由涂鸦生成，以及复杂人物姿态控制。
- 像素级构图还原承诺。
- 使用 AI 艺术字承载标题、价格、按钮或其他必须准确传达的信息。
