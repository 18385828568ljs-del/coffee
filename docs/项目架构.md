# 项目架构

## 系统定位

单店咖啡商城系统，Spring Boot 单体应用。一个进程同时提供小程序 API、商家后台、定时任务。

## 技术栈

**后端**
- Spring Boot 2.5.13 + MyBatis 2.2.2
- MySQL 8.0 + Druid 连接池
- Shiro 1.9.0 权限管理
- Quartz 定时任务
- 腾讯云 COS 对象存储

**前端**
- uni-app 小程序（Vue 2 + uView UI）
- Thymeleaf 后台管理页面

## 架构分层

```
小程序 ←→ Controller ←→ Service ←→ Mapper ←→ MySQL
                           ↓
                     推荐/画像/营销引擎
```

**Controller**: 参数校验、身份解析、响应封装  
**Service**: 业务规则、事务控制、金额计算  
**Mapper**: SQL 执行、结果映射  

## 核心业务流程

### 商城购物

```
商品列表 → 画像推荐排序 → 加入购物车（记录加购证据）
  → 创建订单 → 服务端重算金额（活动+会员折扣）
  → 余额支付（乐观锁扣款）→ 完成
```

### 扫码点单

```
扫码识别桌号 → 浏览菜单（画像排序）→ 选规格加购
  → 提交订单 → 服务端重算金额
  → 余额支付（状态机锁定+扣款）
  → 分配取餐号 → 商家接单制作 → 叫号出餐
```

### 用户画像推荐

```
浏览/加购/购买 → 行为证据表
  ↓
定时任务（每10分钟增量、每天03:00全量）
  ↓
画像计算（权重8/4/1 × 时间衰减1.0/0.6/0.3）
  ↓
生成标签（商品/分类/产地/规格 + 价格区间）
  ↓
商品列表排序（价格距离优先 → 标签匹配度）
```

详见[用户画像推荐功能文档](用户画像推荐功能.md)

## 并发安全设计

### 库存防超卖
```sql
UPDATE t_product 
SET stock = stock - #{quantity}
WHERE product_id = #{productId} 
  AND stock >= #{quantity}  -- 关键：WHERE条件保证库存充足
```

### 余额防透支
```sql
UPDATE t_wallet
SET balance = balance - #{amount}
WHERE user_id = #{userId} 
  AND balance >= #{amount}  -- WHERE条件防止透支
```

### 订单防重复支付
```java
// 先用乐观锁抢占订单状态
int affected = updateOrderStatus(orderId, 待支付, 制作中);
if (affected == 0) throw new Exception("订单状态已变更");

// 状态锁定成功后才扣款
walletService.deduct(userId, amount);
```

### 取餐号并发生成
```java
// 单机环境：ConcurrentHashMap + AtomicInteger
private final ConcurrentHashMap<String, AtomicInteger> PICKUP_NO_SEQ;

String generatePickupNo() {
    AtomicInteger seq = PICKUP_NO_SEQ.computeIfAbsent(today, k -> {
        return new AtomicInteger(dbMaxValue); // 启动时从DB初始化
    });
    return String.format("%03d", seq.incrementAndGet());
}
```

**多实例部署需改造**: 取餐号使用 Redis INCR 或数据库序列

## 定时任务

| 任务 | 周期 | 说明 |
|------|------|------|
| 用户画像增量刷新 | 每10分钟 | 处理有行为/订单变化的用户 |
| 用户画像全量校准 | 每天03:00 | 重算全部用户 + 清理180天前数据 |
| 订单超时取消 | 按需配置 | 待支付订单超时自动取消 |

任务配置存储在 `sys_job` 表，Quartz 自动加载。

## 数据库

**初始化顺序**:
1. `sql/ry_20210924.sql` - 若依框架表
2. `sql/quartz.sql` - Quartz 调度表
3. `sql/coffee_all_business.sql` - 业务表 + 菜单 + 任务配置
4. `sql/coffee_test_data.sql` - 测试数据（可选）

**核心业务表**: 约 30 张
- 商城: t_product, t_order, t_cart, t_category, t_address
- 点单: t_scan_order, t_scan_product, t_scan_cart, t_scan_table_qrcode
- 会员: t_member, t_wallet, t_wallet_log, t_recharge_template
- 画像: t_user_profile, t_user_behavior_event
- 活动: t_marketing_activity, t_offline_activity

## 身份认证

**商家后台**: Shiro Session + Cookie  
**小程序**: JWT Token  
- 携带方式: `Authorization: Bearer <token>` 或 `X-Wx-Token`
- 解析: `WxUserTokenService.resolveUserId(request)`

## 外部依赖

- **微信服务**: 小程序登录、订阅消息推送
- **腾讯云 COS**: 商品图片存储
- **AI 图片服务**: 商品图片润色（第三方 API）

## 当前限制与改进方向

### 单机部署限制
- 取餐号生成使用内存计数器，多实例会重复
- 缺少分布式锁
- 定时任务无法多实例协调

### 性能瓶颈
- 缺少 Redis 缓存（画像、商品列表）
- 画像计算串行处理
- 缺少异步任务队列

### 配置管理
- 运营参数硬编码（画像权重、衰减系数）
- 密钥明文存储在配置文件（安全风险）

### 多实例改造建议
1. 取餐号改用 Redis INCR
2. Quartz 启用集群模式（已支持，需配置）
3. 画像缓存使用 Redis（TTL=10分钟）
4. 增加分布式锁（Redisson）

### 待完成功能
- 真实支付接入（微信支付）
- 在线充值
- 接口限流
- 监控告警

## 项目成熟度

- **代码质量**: 中等偏上，结构清晰，有测试覆盖
- **并发安全**: 单机环境安全，多实例需改造
