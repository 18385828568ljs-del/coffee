## 项目介绍

### 这个项目是什么

**咖啡商城小程序**是一个面向咖啡店的**扫码点单系统**，包含以下核心功能：

- **扫码点单** - 顾客扫桌面二维码进入小程序，浏览商品、加入购物车、余额支付、实时履约（取餐号、预计等待时间、催单）
- **商家后台** - 实时接收订单、管理商品、订单履约管理（接单、制作、叫号）
- **会员钱包** - 余额消费、消费流水、充值模板、会员等级折扣；在线充值待接入
- **营销活动** - 满减活动、指定商品优惠、活动时段控制
- **线下活动** - 活动发布、用户预约报名、状态管理
- **AI图片润色** - 商家上传商品图片，AI自动优化图片质量
- **支付能力** - 当前支持余额支付；微信或第三方支付待接入
- **用户画像推荐** - 根据近 180 天的浏览、首次加购和有效购买生成内部偏好标签，自动调整商城与点单商品顺序

规划中的社区能力包括个性化皮肤、朋友圈素材与定制卡片、人像捏制，以及卡池抽卡和集卡玩法。

## 项目怎么使用

### 环境要求

- JDK 1.8+
- MySQL 8.0+
- Maven 3.6+
- Node.js 14+
- 微信开发者工具

### 后端启动步骤

#### 1. 克隆项目
```bash
git clone https://github.com/你的用户名/coffee-shop.git
cd coffee-shop
```

#### 2. 创建数据库

```bash
# 登录MySQL
mysql -u root -p

# 创建数据库
CREATE DATABASE coffee DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE coffee;

# 执行若依框架SQL
mysql -u root -p coffee < sql/ry_20210924.sql

# 执行定时任务框架SQL
mysql -u root -p coffee < sql/quartz.sql

# 执行业务表SQL（合并版，一次搞定）
mysql -u root -p coffee < sql/coffee_all_business.sql
```

#### 3. 修改配置文件

编辑 `src/main/resources/application.yml` 和 `application-druid.yml`

```yaml
# 数据库配置
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/coffee?useUnicode=true&characterEncoding=utf8
    username: root
    password: 你的数据库密码
    
# 腾讯云COS配置（建议使用环境变量）
cos:
  secret-id: ${COS_SECRET_ID}
  secret-key: ${COS_SECRET_KEY}
```

#### 4. 启动项目
```bash
# 使用Maven启动
mvn clean install
mvn spring-boot:run

# 或在IDE中运行 RuoYiApplication.java
```

#### 5. 访问后台
```
URL: http://localhost:8080
账号: admin
密码: admin123
```

### 小程序端启动步骤

#### 1. 进入小程序目录
```bash
cd RuoYi-AbuCoder-UniAppWx/Ruoyi-AbuCoder-UniApp-WX
```

#### 2. 修改API地址
编辑 `utils/apiconfig.js`
```javascript
const DEFAULT_BASE_URL = 'http://127.0.0.1:8080' // 改为你的后端地址
```

#### 3. 导入微信开发者工具
- 打开微信开发者工具
- 导入项目目录
- 填写AppID
- 编译运行

## 已知问题与风险

### 高优先级问题（P0）

#### 1. 真实支付与在线充值尚未接入
- **现状**：商城与扫码点单仅支持余额支付，在线充值接口尚未开放
- **影响**：用户无法通过微信或第三方渠道付款、充值或退款
- **后续处理**：接入支付下单、回调验签、状态补偿、退款和对账

#### 2. 密钥安全存储
- **现状**：配置文件直接写密钥
- **风险**：代码泄露导致密钥泄露
- **改进方案**：使用环境变量或密钥管理服务

#### 3. 订阅消息授权机制
- **机制**：微信小程序订阅消息为一次性授权
- **说明**：用户授权一次只能发送1条消息，消息发送后授权失效
- **影响**：用户每次下单都需要重新授权才能收到取餐通知
- **处理**：扫码确认页在创建订单前统一请求授权，避免重复弹窗

### 已解决问题

#### 1. 订单金额被篡改
- **解决方案**：后端重新计算所有金额，忽略前端传入的金额参数
- **实现位置**：`OrderApiController.java` 和 `ScanOrderServiceImpl.java`

#### 2. 并发超卖
- **解决方案**：SQL WHERE条件：`UPDATE ... SET stock = stock - #{quantity} WHERE stock >= #{quantity}`
- **实现位置**：`TProductMapper.xml`

#### 3. 会员折扣动态配置
- **解决方案**：从 `sys_config` 读取折扣率，数据库字段仅作快照
- **实现位置**：`MemberService.java`
